# プロダクト概要

## 目的

- 実サービスを想定したECサイトを、**モジュラーモノリス + DDD + イベントソーシング**で構築する。
- 単純なCRUDではなく、在庫の同時更新・決済・アクセス集中など「整合性と負荷」が問題になる箇所を、ロック・キュー・イベントで解決する経験を積む。
- **開発者本人のコーディング力向上**が最優先の目的。実装は手で書き、AI はレビューと質問への回答に使う（[ADR-0008](../adr/0008-ai-usage-policy.md)）。

## 利用者

| 利用者 | できること |
|---|---|
| 訪問者（未ログイン） | 商品の閲覧・検索のみ。購入はできない |
| 会員 | Google アカウントまたはメールアドレスとパスワードでログインし、カート・購入・注文履歴を利用する |
| 管理者 | 商品・在庫・注文を管理する |

## MVP スコープ

優先度は Must / Should / Could。詳細な振る舞いはモデリング（[`../modeling/`](../modeling/)）とTask Issueで決める。

| ID | 内容 | 優先度 |
|---|---|---|
| FR-001 | 訪問者・会員が商品一覧・詳細を閲覧できる | Must |
| FR-002 | 商品をカテゴリ・価格などで絞り込み、並び替えできる（DB検索） | Must |
| FR-003 | Google アカウントでログイン・ログアウトできる | Must |
| FR-004 | 会員がカートに商品を追加・変更・削除できる | Must |
| FR-005 | 会員がカートの内容で注文し、Stripe で決済できる | Must |
| FR-006 | 注文時に在庫を引き当て、売り越し（在庫以上の販売）が起きない | Must |
| FR-007 | 決済結果（Stripe Webhook）に応じて注文・在庫が更新される | Must |
| FR-008 | 会員が自分の注文履歴・注文状態を確認できる | Must |
| FR-009 | 管理者が商品・価格・在庫を登録・更新できる | Must |
| FR-010 | 管理者が注文の状態を確認・更新（発送・キャンセル）できる | Should |
| FR-011 | 注文確定などの通知メールを送る | Could |
| FR-012 | メールアドレスとパスワードで会員登録（メール確認あり）・ログインできる | Must |
| FR-013 | パスワードを忘れた会員が再設定できる | Must |
| FR-014 | 訪問者・会員が商品名のキーワードで商品を検索できる（DB の部分一致） | Must |

## 非機能要求（MVP 時点）

| ID | 分類 | 内容 |
|---|---|---|
| NFR-001 | 整合性 | 同時注文が集中しても、在庫数を超えて引き当てない（並行実行テストで検証する） |
| NFR-002 | 整合性 | 同じ注文リクエスト・同じ Webhook を複数回受けても、結果は1回分になる（冪等性） |
| NFR-003 | 負荷 | 注文受付が集中してもAPIがタイムアウトしないよう、重い処理はキューで非同期に実行する |
| NFR-004 | 監査 | 注文の状態変化はイベントとして全て残り、後から経緯を追える |
| NFR-005 | セキュリティ | トークンをブラウザの JavaScript から読めない形で保持する |
| NFR-006 | 保守性 | モジュール間・層間の依存方向を CI で機械的に検査する |

数値目標（応答時間・同時接続数など）は、負荷試験の環境ができた時点で追加する。

## 対象外（MVP ではやらない）

- ゲスト購入（未ログインでの購入）
- Apple ログイン
- デジタル商品の販売・ダウンロード
- ウィッシュリスト、レビュー、クーポン、ポイント
- 全文検索エンジン（Elasticsearch / OpenSearch）
- 配送業者との連携、多通貨、多言語
- AWS へのデプロイ（別フェーズで設計する）

## 将来の対象候補

| 候補 | メモ |
|---|---|
| 未ログインの仮カート | 訪問者がカートに入れ、ログイン時に会員のカートへ統合する。統合ルールはモデリング時に検討 |
| 全文検索 | MVP は DB の部分一致検索（FR-014）で済ませる。商品数や検索の要件が増えたら OpenSearch を導入し、商品イベントから検索インデックスを更新する（CQRS の読み取りモデルの一つとして追加できる） |
| フラッシュセール | 注文受付キューの効果を負荷試験で確認する題材にする |
