# ADR-0001: フロントエンドとバックエンドを1つのリポジトリで管理する

- 状態: 採用
- 日付: 2026-11-07

## 背景

Next.js（frontend）と Laravel（backend）の2つのアプリケーションを作る。開発者は1人で、API の変更と画面の変更を同時に行うことが多い。

## 検討した選択肢

### A. 1つのリポジトリ（`frontend/` と `backend/`）
- 良い点: API と画面の変更を1つの PR でレビューできる。docs・ADR・Issue を1か所で管理できる。
- 悪い点: CI で変更のあったディレクトリだけを検査する設定が必要。

### B. リポジトリを分ける
- 良い点: それぞれの CI・権限が単純。
- 悪い点: 1つの機能が2つの PR に分かれ、レビューと Issue の管理が煩雑になる。

## 決定

A を採用する。ルートに `frontend/`・`backend/`・`docs/` を置く。パッケージ管理ツールによるモノレポ構成（Turborepo など）は使わない（言語が違い、共有するコードがないため）。

## 影響

- CI はパスで絞り込み、`frontend/**` と `backend/**` の変更ごとにジョブを分ける。
- API の型をフロントと共有する方法（OpenAPI から生成するなど）は、API を作り始める時点で決める。
