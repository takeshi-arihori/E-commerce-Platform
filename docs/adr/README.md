# Architecture Decision Records（ADR）

アーキテクチャ、品質、外部とのやり取り、将来の変更コストに大きく影響する判断を記録する。
**採用した案だけでなく、採用しなかった案とその理由も残す。**

## 状態

- **提案中**: 検討中。この ADR に依存する Task には着手しない。
- **採用**: 決定済み。本文は書き換えない（誤字の修正を除く）。
- **置換済み**: 新しい ADR に置き換えた。置き換えた ADR へのリンクを書く。
- **不採用**: 検討した結果、採用しなかった。

## 命名規則

`NNNN-<英語の短い名前>.md`（例: `0009-inventory-reservation.md`）。

## テンプレート

```markdown
# ADR-XXXX: 判断のタイトル

- 状態: 提案中 | 採用 | 置換済み（→ ADR-YYYY）| 不採用
- 日付: YYYY-MM-DD

## 背景
どんな課題があり、なぜ判断が必要か。

## 制約
選択肢を制限する条件。

## 検討した選択肢
### A. ...
- 良い点
- 悪い点

### B. ...

## 決定
何を採用したか。

## 理由
なぜこのプロジェクトで最もよいトレードオフか。

## 採用しなかった案と理由

## 影響
簡単になること、難しくなること、新しく生まれる制約。
```
