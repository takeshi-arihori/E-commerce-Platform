# ADR-0003: データベースの選定

- 状態: 提案中（推奨: PostgreSQL）
- 日付: 2026-11-07

## 背景

イベントストア、在庫の悲観ロック、Outbox、コンテキストごとのテーブル分割を1つの RDB で実現する。候補は PostgreSQL と MySQL（InnoDB）。

## 制約

- Laravel が正式に対応していること（両方対応）。
- 将来 AWS のマネージドサービス（RDS / Aurora）で動かせること（両方対応）。
- ロックの学習が目的の一つ。

## 比較

| 観点 | PostgreSQL | MySQL（InnoDB） | このプロジェクトへの影響 |
|---|---|---|---|
| 既定の分離レベル | READ COMMITTED | REPEATABLE READ | MySQL はロックを取る読み込みで**ギャップロック / ネクストキーロック**がかかり、範囲検索や存在しない行への INSERT で予想外の待ちやデッドロックが起きやすい。理解すれば学びになるが、最初は原因が分かりにくい |
| `FOR UPDATE SKIP LOCKED` / `NOWAIT` | ある | ある（8.0 以降） | Outbox のリレー・ジョブの取り出しはどちらでも書ける |
| アドバイザリロック | `pg_advisory_xact_lock`（トランザクション終了で自動解放） | `GET_LOCK`（接続単位。明示的に解放が必要） | MySQL は解放漏れ・接続の使い回しでロックが残る危険がある |
| DDL のトランザクション | DDL もロールバックできる | DDL は暗黙にコミットされる | PostgreSQL はマイグレーションが途中で失敗しても元に戻る |
| JSON | `jsonb`（GIN インデックスで中身を検索できる） | `JSON`（生成列・複数値インデックスで検索する） | イベントの payload を調べるときは PostgreSQL が楽。主にイベントを順に読むだけなら差は小さい |
| 部分インデックス | ある（`WHERE status = 'active'` の行だけ一意にする、など） | ない（関数インデックスで近いことはできる） | 「有効な引き当ては1つだけ」などの制約を DB で表しやすい |
| `RETURNING` | ある | ない | 更新した結果をもう一度 SELECT しなくて済む |
| UUID | `uuid` 型（18 は `uuidv7()` 関数もある） | `BINARY(16)` などで保存し、変換が必要 | ID に UUID v7 を使う予定のため、PostgreSQL が扱いやすい |
| コンテキストごとの分割 | **schema** で分けられる（`ordering.orders`） | schema = database。分けるとテーブルの接頭辞か複数の database になる | 境界を DB の権限で守る、将来の分割の練習ができる |
| 日本語の全文検索 | 標準では弱い（`pg_trgm` / `pg_bigm` などの拡張が必要） | `FULLTEXT` + `ngram` パーサーが標準である | **MySQL の利点**。ただし MVP は全文検索をしない（将来は OpenSearch を検討） |
| イベントの全体の順番 | 連番（シーケンス）は採番順とコミット順がずれる | `AUTO_INCREMENT` も同じ問題がある | どちらでも、プロジェクションが取りこぼさない工夫が必要（差はない） |
| 日本の Laravel の現場 | 増えている | **多い** | 転職・実務への近さを重視するなら MySQL に利点 |
| これまでの経験 | 参考リポジトリ（kakei_app、hutzper-coading-test）で使用 | - | 環境構築でつまずきにくい |

## 決定（案）

**PostgreSQL を推奨する。** 開発者の判断で確定する。

## 理由

- イベントストア・Outbox・コンテキストごとの schema 分割・部分インデックス・トランザクション内の DDL など、このプロジェクトで使う機能が揃っている。
- ロックの動きが素直で、「なぜ待ったか」を説明しやすい。悲観ロックや楽観ロックの基本を学ぶ段階に向いている。
- MySQL の利点（日本語の全文検索、実務での採用の多さ）は、MVP の範囲では効いてこない。

## MySQL を選ぶ場合

- ギャップロックを含めた InnoDB のロックを学ぶことを目的に加える。並行実行テストでデッドロックの再現と対策を行う。
- コンテキストの分割はテーブル名の接頭辞（`ordering_orders`）で行う。
- イベントストアの検索が必要な項目は、JSON から生成列を作ってインデックスを張る。

## 影響

- 開発環境の compose・CI に PostgreSQL のコンテナを入れる。
- Laravel のマイグレーションでコンテキストごとの schema を作る必要がある。
