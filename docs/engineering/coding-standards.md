# コーディング規約

## 共通

- まずシンプルに動かし、テストで守ってから改善する。必要になる前に抽象化しない。
- **DRY**: 同じ知識（ルールや意味）を2か所に書かない。見た目が似ているだけのコードは共通化しない。
- **秘匿情報**: `.env` と秘密の値はコミットしない。環境変数を追加したら `.env.example` も更新する。トークン・個人情報をログに出さない。
- 命名はユビキタス言語に合わせる（[glossary.md](../modeling/glossary.md)）。用語集にない業務用語をコードに出したら、用語集に追加する。

## バックエンド（PHP / Laravel）

### 基本

- すべてのファイルに `declare(strict_types=1);` を書く。
- クラスは既定で `final`。値オブジェクトは `readonly`。
- 引数・戻り値・プロパティに型を書く。`mixed` と配列の多用を避け、意味のある値はクラスにする。
- フォーマットは **Laravel Pint**、静的解析は **Larastan（PHPStan）**。レベルは環境構築時に決め、上げることはあっても下げない。
- テストは **Pest**。

### 層ごとのルール（教材に合わせる）

| 対象 | ルール |
|---|---|
| エンティティ・値オブジェクト | **常に正しいインスタンスしか存在させない**。生成時に不変条件を確認し、外から状態を直接書き換えるセッターを作らない（教材: モデリング/実装ガイド 第2章 2.3） |
| 生成と再構成 | 新規作成用のメソッドと、DB の値から復元するメソッドを分ける（教材: サンプルコード&FAQ 第3章 3.2） |
| ドメイン層 | Laravel に依存しない（Facade、Eloquent、`Illuminate\Support\Collection`、ヘルパー関数を使わない） |
| リポジトリ | interface はドメイン層、実装はインフラ層。集約単位で保存・取得する |
| Eloquent モデル | インフラ層だけで使う。ドメインのエンティティと Eloquent モデルを兼用しない |
| ユースケース | 1クラス1ユースケース、公開メソッドは `execute()` だけ。Controller から呼ぶユースケースは1つ。ユースケースからユースケースを呼ばない（教材: サンプルコード&FAQ 第8章 8.6.1） |
| ユースケースの戻り値 | ドメインオブジェクトを返さず、ユースケース層の DTO を返す |
| 参照系 | 一覧・画面表示用の取得は、ユースケース層に interface を置いたクエリサービスで行う（軽量 CQRS） |
| Controller | リクエストの検証・ユースケースの呼び出し・レスポンスへの変換だけを行う |
| 例外 | ドメインのルール違反はドメイン層の例外、ユースケースでの失敗（見つからない、権限がない）はユースケース層の例外にする。HTTP ステータスへの変換はプレゼンテーション層でまとめて行う |

### 依存方向の検査

- 層とコンテキストの依存ルール（[overview.md](../architecture/overview.md#バックエンドのレイヤー)、[modules.md](../architecture/modules.md#コンテキスト間のルール)）を **Deptrac** か **Pest の arch テスト**で検査し、CI で失敗させる。どちらを使うかは環境構築時に決める。

### DB

- テーブル名・列名は `snake_case`。
- 主キーは UUID（v7）を使い、ID はアプリケーション側で生成する（集約を保存する前に ID が決まるようにするため）。
- マイグレーションは追加のみ。リリース済みのマイグレーションを書き換えない。
- ループの中でクエリを発行しない（N+1 を作らない）。
- ロックとトランザクションは [consistency.md](../architecture/consistency.md) に従う。

## フロントエンド（TypeScript / Next.js）

- `strict: true`。`any` と型アサーション（`as`）で不整合を隠さない。
- 外部からの入力（API のレスポンス・フォーム・URL パラメータ）は zod で検証する。
- Laravel API を呼ぶコード・Cookie を扱うコードには `import "server-only"` を書く。
- 既定は Server Components。状態や操作が必要な部品だけ Client Components にする。
- フォーマットと静的解析のツール（ESLint + Prettier / Biome）は環境構築時に決める。
- ファイル名は kebab-case（React コンポーネントだけ PascalCase）。
